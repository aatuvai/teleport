As with all Teleport users, the Teleport Auth Service authenticates the
`{props.role ?? "access-plugin"}` user by issuing short-lived TLS credentials. In this case, we
will need to request the credentials manually by *impersonating* the
`{props.role ?? "access-plugin"}` role and user.

If you are running a self-hosted Teleport Enterprise deployment and are using
`tctl` from the Auth Service host, you will already have impersonation
privileges.

To grant your user impersonation privileges for `{props.role ?? "access-plugin"}`, define a user
named `{props.role ?? "access-plugin"}` and a role named `{props.role ?? "access-plugin"}-impersonator` by adding
the following YAML document into a file called `{props.role ?? "access-plugin"}-impersonator.yaml`:

<CodeBlock>
{
 `kind: user
  metadata:
    name: ${ props.role ?? "access-plugin" }
  spec:
    roles: ['${ props.role ?? "access-plugin" }']
  version: v2
  ---
  kind: role
  version: v7
  metadata:
    name: ${ props.role ?? "access-plugin" }-impersonator
  spec:
    allow:
      impersonate:
        roles:
        - ${ props.role ?? "access-plugin" }
        users:
        - ${ props.role ?? "access-plugin" }`
}
</CodeBlock>

Create the user and role:

<CodeBlock>
{
 `$ tctl create -f ${ props.role ?? "access-plugin" }-impersonator.yaml
  user "${ props.role ?? "access-plugin" }" has been created
  role "${ props.role ?? "access-plugin" }-impersonator" has been created`
}
</CodeBlock>

Assign this role to the user you plan to use to generate credentials for the
`{props.role ?? "access-plugin"}` role and user:

<DocsPagesIncludesAddRoleToUser role={(props.role ?? "access-plugin") + "-impersonator"} />

You will now be able to generate signed certificates for the `{props.role ?? "access-plugin"}`
role and user.

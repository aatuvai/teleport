
To allow IAM Role `{props.role1 ?? "role1"}` to assume IAM Role `{props.role2 ?? "role2"}`, the following is
generally required:

**1. Configure Trust Relationships on {props.role2 ?? "role2"}**

`{props.role1 ?? "role1"}` or its AWS account should be set as `Principal` in `{props.role2 ?? "role2"}`'s trust
policy.
<Tabs>
<TabItem label="Role as principal">

Assign <Var name="aws-account-id"/> to your AWS account ID:
<CodeBlock>
{
 `{
    "Version": "2012-10-17",
    "Statement": [
      {
        "Effect": "Allow",
        "Principal": {
          "AWS": "arn:aws:iam::<Var name="aws-account-id"/>:role/${ props.role1 ?? "role1" }"
        },
        "Action": "sts:AssumeRole"
      }
    ]
  }`
}
</CodeBlock>
</TabItem>
<TabItem label="Account as principal">

Assign <Var name="aws-account-id"/> to your AWS account ID:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::<Var name="aws-account-id"/>:root"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
```
</TabItem>
<TabItem label="Cross-account with external-id">

Assign <Var name="external-aws-account-id"/> to an external AWS account ID:

<CodeBlock>
{
 `{
    "Version": "2012-10-17",
    "Statement": [
      {
        "Effect": "Allow",
        "Principal": {
          "AWS": "arn:aws:iam::<Var name="external-aws-account-id"/>:role/${ props.role1 ?? "role1" }"
        },
        "Action": "sts:AssumeRole",
        "Condition": {
          "StringEquals": {
            "sts:ExternalId": "example-external-id"
          }
        }
      }
    ]
  }`
}
</CodeBlock>
</TabItem>

</Tabs>

**2. Configure Permissions Policies on {props.role1 ?? "role1"}**

`{props.role1 ?? "role1"}` requires `sts:AssumeRole` permissions, for example:
<CodeBlock>
{
 `{
      "Version": "2012-10-17",
      "Statement": [
          {
              "Action": "sts:AssumeRole",
              "Effect": "Allow",
              "Resource": "arn:aws:iam::<Var name="aws-account-id"/>:role/${ props.role2 ?? "role2" }"
          }
      ]
  }`
}
</CodeBlock>

Note that this policy can be omitted when `{props.role1 ?? "role1"}` and `{props.role2 ?? "role2"}` are in the same
AWS account and `{props.role1 ?? "role1"}`'s full ARN is configured as Principal in `{props.role2 ?? "role2"}`'s
trust policy.

**3. Configure Permissions Boundary on {props.role1 ?? "role1"}**

If `{props.role1 ?? "role1"}` does not have an attached
[Permissions boundary](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_boundaries.html)
then you can skip this step.
Otherwise, the boundary policy attached to `{props.role1 ?? "role1"}` must include
`sts:AssumeRole` permissions, for example:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Action": "sts:AssumeRole",
            "Effect": "Allow",
            "Resource": "*"
        }
    ]
}
```
